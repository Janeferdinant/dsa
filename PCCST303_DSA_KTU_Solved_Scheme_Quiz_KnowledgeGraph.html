Q1Time complexity (growth of log-functions)Complexity: 3 marks
Scheme: Correct complexity — 3 marks

Answer. For a halving search process such as binary search, the recurrence is T(n) = T(n/2) + c, which solves to T(n) = O(log n).

Ordering the given functions by growth rate (slowest → fastest):

log n  <  (log n)² = log²n

So between the choices log n, (log n)² and log²n − 3, the dominant-but-smallest complexity for binary search is O(log n), while log²n grows strictly faster than log n.

Q3Sparse Matrix — definition and exampleReconstructedDefinition: 2 + Example: 1
Scheme: Definition — 2 marks + example — 1 mark

Definition. A matrix in which most of the elements are zero is called a sparse matrix. Formally, a matrix with m × n elements is sparse when the number of non-zero elements is much smaller than m·n (typically > 50% zeros). It is stored compactly as a triplet list (row, column, value) to save memory.

Example (3 × 3 sparse matrix):

A = | 0  0  5 |
    | 0  0  0 |
    | 3  0  0 |

Triplet form:  (0,2,5)  (2,0,3)      → only 2 non-zero entries out of 9.
Q4Binary Search algorithmReconstructedAlgorithm: 3 marks
Scheme: Correct algorithm / pseudo / program code — 3 marks
Algorithm BinarySearch(A[0..n−1], key)
1.  low ← 0;  high ← n − 1
2.  while low ≤ high do
3.      mid ← ⌊(low + high) / 2⌋
4.      if A[mid] = key        then return mid          // found
5.      else if key < A[mid]  then high ← mid − 1
6.      else                      low  ← mid + 1
7.  return −1                                                // not found
// Works only on a SORTED array.  Time: O(log n)   Space: O(1)

Scheme: Any two methods with example — 1.5 marks each. Acceptable: Adjacency matrix, adjacency list, set

1. Adjacency Matrix — a V × V array where A[i][j] = 1 (or weight) if edge (i, j) exists, else 0. Space = O(V²).

2. Adjacency List — an array of linked lists; list i stores all vertices adjacent to vertex i. Space = O(V + E).

Graph:  0—1, 0—2, 1—3

   0 1 2 3                0 → 1 → 2

Matrix = fast edge lookup O(1), but wastes space on sparse graphs. List = memory-efficient and ideal for traversals (BFS/DFS).

Q8Priority Queue (concept)Reconstructed3 marks
Scheme: Q8 text not legible in source PDF — high-probability KTU question answered

Answer. A priority queue is a queue in which each element has a priority; the element with the highest (or lowest) priority is deleted first, regardless of arrival order.

  • Insert — adds element with its priority (O(1) at rear, or O(log n) in a heap).
  • Delete — removes the max-priority element (O(n) by scanning, or O(log n) in a heap).

Applications: CPU scheduling, Dijkstra's algorithm, Huffman coding, printer queues. Implementation: heap (best) or sorted/unsorted array.

Q9Asymptotic NotationsModule 1
Scheme: (a) Big O with explanation + graph — 2 • Big Ω with graph — 2 • Big Θ with graph — 1

(a) Big-O (Upper Bound) — O(g(n))

f(n) = O(g(n)) if there exist constants c > 0 and n₀ ≥ 1 such that f(n) ≤ c·g(n) for all n ≥ n₀. g(n) is an asymptotic upper bound: f never grows faster than g. Example: 3n + 2 = O(n) (take c = 4, n₀ = 2).

Big-Ω (Lower Bound) — Ω(g(n))

f(n) = Ω(g(n)) if there exist constants c > 0, n₀ such that f(n) ≥ c·g(n) for all n ≥ n₀. g(n) is an asymptotic lower bound. Example: 3n + 2 = Ω(n) (take c = 3).

Big-Θ (Tight Bound) — Θ(g(n))

f(n) = Θ(g(n)) iff f(n) = O(g(n)) and f(n) = Ω(g(n)). g(n) is both an upper and lower bound — f grows at exactly the same rate. Example: 3n + 2 = Θ(n).

(a) Infix to Postfix conversion using a stack

Algorithm InfixToPostfix(E)
1.  for each token t in E (left → right) do
2.      if t is an operand      then append t to output
3.      else if t = '('         then PUSH '('
4.      else if t = ')'         then POP and append until '(' ; POP '('
5.      else  // operator
6.          while stack ≠ empty AND top ≠ '('
7.                AND precedence(top) ≥ precedence(t) do
8.                POP and append to output
9.          PUSH t
10. while stack ≠ empty do POP and append to output
// Precedence: * /  = 2   >   + −  = 1   (left-associative)

(b) Bubble Sort — complexity

Algorithm BubbleSort(A, n)                      // optimized
1.  for i ← 0 to n−2 do
2.      swapped ← false
3.      for j ← 0 to n−i−2 do
4.          if A[j] > A[j+1] then
5.              swap A[j], A[j+1];  swapped ← true
6.      if swapped = false then break        // already sorted

Q11Queue operations & Linked List insertionModule 2
Scheme: (a) Queue insertion — 2.5 + deletion — 2.5 • (b) Insert at beginning — 2 + insert at end — 2

(a) Circular Queue — ENQUEUE (INSERT) and DEQUEUE (DELETE)

Algorithm ENQUEUE(Q, item)
1.  if (rear + 1) mod MAX = front  then print "Queue Overflow"; return
2.  if front = −1  then front ← 0            // first element
3.  rear ← (rear + 1) mod MAX
4.  Q[rear] ← item

Algorithm DEQUEUE(Q)
1.  if front = −1  then print "Queue Underflow"; return NULL
2.  item ← Q[front]
3.  if front = rear  then front ← −1; rear ← −1   // last element
4.  else front ← (front + 1) mod MAX
5.  return item

(b) Singly Linked List — INSERT AT BEGINNING and INSERT AT END

Algorithm INSERT_AT_BEGINNING(head, data)
1.  newNode ← getnode();  newNode.data ← data
2.  newNode.next ← head
3.  head ← newNode
4.  return head                        // Time: O(1)

Algorithm INSERT_AT_END(head, data)
1.  newNode ← getnode();  newNode.data ← data;  newNode.next ← NULL
2.  if head = NULL  then head ← newNode; return head
3.  temp ← head
4.  while temp.next ≠ NULL do  temp ← temp.next   // traverse to last
5.  temp.next ← newNode
6.  return head                        // Time: O(n)

Algorithm DIJKSTRA(G, src)
1.  dist[src] ← 0;  dist[v] ← ∞ for all other v;  S ← ∅

3.  while PQ ≠ empty do
4.      u ← extract-min(PQ);  S ← S ∪ {u}

6.          if dist[u] + w < dist[v]  then dist[v] ← dist[u] + w;  parent[v] ← u;  decrease-key(PQ, v)

Q14BFS algorithm & DFS from vertex EModule 3
Scheme: (a) Correct algorithm — 3 + DFS on the given graph from source E (any correct answer) — 3 • (b) Correct algorithm — 3

(a) Breadth-First Search (BFS) algorithm

Algorithm BFS(G, s)
1.  for each vertex v: visited[v] ← false
2.  Q ← empty queue;  visited[s] ← true;  ENQUEUE(Q, s)
3.  while Q ≠ empty do
4.      u ← DEQUEUE(Q);  visit(u)
5.      for each neighbour w of u do
6.          if visited[w] = false then visited[w] ← true; ENQUEUE(Q, w)
// Time: O(V + E)  with adjacency list. Uses a QUEUE (FIFO).

DFS on the given graph starting from source vertex E (adjacency taken alphabetically):

Graph edges:  A—B, A—C, B—D, B—E, C—F, D—G, E—G

DFS-Visit(E):  visit E → neighbours of E: B, G
   B (first) → neighbours of B: A, D, E(visited)
      A → neighbours of A: B(visited), C
         C → neighbours of C: A(visited), F
            F → all neighbours visited → backtrack
   G → neighbours of G: D, E(visited)
      D → neighbours of D: B(visited), G(visited) → backtrack
DFS order from E: E → B → A → C → F → G → D (any correct traversal accepted)

(b) Kruskal's Minimum Spanning Tree algorithm

Algorithm KRUSKAL(G)
1.  sort all edges in non-decreasing order of weight
2.  for each vertex v: MAKE-SET(v)
3.  T ← ∅
4.  for each edge (u, v, w) in sorted order do
5.      if FIND-SET(u) ≠ FIND-SET(v) then      // no cycle formed
6.          T ← T ∪ {(u,v)};  UNION(u, v)
7.  return T                      // T has V−1 edges, total weight = MST cost

Uses the Union-Find (Disjoint Set) data structure; greedy choice of the lightest safe edge; complexity O(E log E).

Q15Hashing with separate chainingModule 4
Scheme: Correct algorithm — 4 marks + explanation with figure — 2 marks

Concept. Hashing maps a key k to a table slot using a hash function h(k) = k mod m. When two keys collide at the same slot, separate chaining stores them in a linked list attached to that slot.

Algorithm CHAINED-HASH-INSERT(T, k)
1.  j ← h(k)
2.  insert k at the head of list T[j]          // O(1)

Algorithm CHAINED-HASH-SEARCH(T, k)
1.  search for key k in list T[h(k)]           // O(list length)

Algorithm CHAINED-HASH-DELETE(T, k)
1.  delete node containing k from list T[h(k)] // O(list length)
Load factor α = n / m; average search Θ(1 + α). No clustering, deletions are easy; needs extra pointer space.
